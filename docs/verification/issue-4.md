# #4 창 선택과 세션 유지 검증

2026-11-03, WSL2 Linux x86_64의 Cline CLI 3.0.74와 공식 DART 2.1.0 Linux CLI가 Windows DART 2.1.0, protocol 2에 연결됐다. 고정 계약 fingerprint와 연결된 Main을 각각 확인했다. 설치는 공개 Release가 아닌 검증된 개발 준비 자산을 사용했다. 회사 Linux와 네트워크는 검증하지 않았다.

공개 식별자 app `2d6a2777-871b-4006-849e-740b134a37ba`, Main `8babf7ad-4464-4fbe-b779-4ee8339c9ea0`, 기존 세션 `4d1c6ca5-cf47-4789-9359-b794f35e90fc`를 사용했다. 공개 CLI로 빈 Sub 창 `6a80b29d-4a20-4b2e-9799-303d17c16340`을 만들어 실제 두 창을 구성했다. 아래는 실제 Cline의 `skills(dart-control)` 요청과 공식 CLI 응답에서 관찰한 결과다.

- 단일 창과 이전 선택이 없는 요청에서 Main을 자동 선택하고 열린 세션과 창 상태를 확인했다. 불필요한 선택 질문은 없었다.
- 두 창에서 기존 Main 세션과 다른 Sub 창을 명시하자 Sub의 새 열린 세션을 생성하고 확인했다. 기존 Main 세션을 다른 창에 사용하지 않았다.
- 명시적 변경 없이 이전 Main 선택을 주자 같은 앱·창·세션을 재확인했다.
- 두 창에서 이전 선택이나 지정이 없는 요청은 양쪽 공개 ID와 역할을 제시하며 `ask_question`을 호출했다. 비대화식 Cline 자동 승인 실행이 Main을 답변으로 제공한 뒤 세션이 생성됐다. 이 자동 응답은 실제 사람의 선택을 검증하지 않는다. 질문 전 업무 명령은 없었다.
- Sub 창을 실제로 닫은 뒤 그 창의 이전 세션으로 계속 요청하자 목록에서 창 부재와 `windowState=closed`를 확인하고, 남은 Main으로 전환할지 물었다. 임의의 업무 명령을 실행하지 않았다.
- Sub 창을 `window show`의 `focus=true`로 실제 포커스한 뒤 기존 Main 작업을 계속하자 Main은 비포커스 상태였지만 같은 Main 창과 세션이 열린 상태로 조회됐다.
- 존재하지 않는 세션으로 명시된 Sub 창의 제어 복구를 요청한 최초 실행은 `SESSION_CLOSED`를 확인하고 이미 요청된 새 세션 생성에 추가 확인을 요구했다 (RED). 지침 변경 후 같은 요청은 같은 Sub 창의 새 세션을 생성하고 열린 창·세션을 확인했다 (GREEN).

테스트용 Sub 창은 작업과 미저장 SQL이 없음을 확인한 뒤 닫았고, 테스트에서 만든 세션을 닫았다. 기존 Main 세션은 보존했다. 세션 ID는 앱 실행에 한정되며 재시작 후 재사용하지 않는다. 회사 환경 및 실제 사용자 선택 응답은 별도 검증 대상이다. Cline 실행 로그는 임시 작업 디렉터리에 보관하며 연결 번들·인증 정보는 기록하지 않았다.
