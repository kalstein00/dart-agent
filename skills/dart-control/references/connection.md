# Connection and one-window session

Resolve `DART` below to this skill's absolute `bin/dart` path. Replace all placeholders from actual responses; do not type them literally.

1. Run `"$DART" version` and `"$DART" contract identity`. Require ok=true, protocolVersion=2, version=2.1.0. Identity.data.contract must have releaseVersion=2.1.0, protocolVersion=2, formatVersion=2 and exactly the fingerprint in dart-agent-distribution.json (algorithm, projectionVersion and value).
2. Ask for an existing official profile name, or a private fresh bundle file and profile name. Windows owner starts DART 2.1.0, opens Settings > External Control, enables Remote Access and issues a one-use connection bundle with the Linux-reachable HTTPS endpoint. Linux cannot enable it or launch the Windows app. No WSL/shared-drive/fixed-port assumption applies.
3. Register only when needed: `"$DART" connection enroll --profile PROFILE --stdin < /private/bundle.json`. Do not cat the bundle. Default official private store is `~/.dart/connections`, or the user's DART_CLI_PROFILE_DIR. Do not edit or copy profile JSON into the skill. Remove the consumed bundle securely according to the user's policy.
4. Run `"$DART" app inspect --profile PROFILE`. Require ok=true and Main's data.version, data.protocolVersion and data.contract independently matching step 1 and distribution pin. Require observation.source=connected-main and observation.appId=data.appId. Record data.appId; never replace Main evidence with local identity.
5. If the user supplies a retained profile/appId/windowId/sessionId binding, keep exactly those identities. Step 4 must inspect that explicit app with `--app APP_ID` and independently recheck compatibility. Then run step 8 directly: reuse only if returned app/window/session identities and open states still match. If stale, closed, missing or mismatched, stop and report it; ask before creating a new binding. Do not fall through to session creation.
6. Only when there is no retained binding and the user requests a new control session, run `"$DART" window list --profile PROFILE --app APP_ID`. If exactly one window exists, select its id. If zero, ask Windows owner to open a window. If multiple and no explicit target, present public IDs/roles and ask; do not choose the first or focused window.
7. Run `"$DART" session create --profile PROFILE --app APP_ID --json '{"windowId":"WINDOW_ID"}'`. Require returned windowId equals selected ID and state=open. Record returned sessionId together with profile/appId/windowId.
8. Verify with `"$DART" session inspect --profile PROFILE --app APP_ID --json '{"windowId":"WINDOW_ID","sessionId":"SESSION_ID"}'`. Require state=open and windowState=open and matching IDs. Reuse this explicit binding for subsequent work; re-inspect before use. Stop on closed/stale/mismatched targets. Do not silently create a replacement session or replay commands.

On errors, preserve the official code/phase/nextAction in a credential-free report. Connection refused, timeout or unreachable endpoint: Windows owner checks app running, Remote Access, endpoint, firewall/network; Linux checks routing to the issued endpoint. Disabled Remote Access: Windows owner enables it. Expired/used bundle or failed enrollment: request a fresh bundle and retry registration explicitly. Trust/certificate change: verify the intended Windows app with its owner before explicit forget/re-enroll. PROFILE_UNAVAILABLE: Linux verifies profile name/location or registers a new bundle. Version/protocol/fingerprint mismatch: install the compatible pinned CLI/app; no business commands. Unknown outcomes require inspection, never blind replay.
