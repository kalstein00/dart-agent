# Connection and window-bound session

Resolve `DART` below to this skill's absolute `bin/dart` path on Linux or `bin/dart.exe` on Windows. Use the host shell's syntax to invoke it. Replace all placeholders from actual responses; do not type them literally.

1. Run `"$DART" version` and `"$DART" contract identity versioned`. Require ok=true, protocolVersion=3 and version=2.1.1. Independently compare identity.data.contract fields releaseVersion, protocolVersion, formatVersion, contractVersion and the complete fingerprint (algorithm, projectionVersion and value) against references/dart-agent-distribution.json versionedContract. Missing, legacy, malformed or unequal values are unknown or mismatch: stop new business commands. A version match alone never approves a different fingerprint; do not update the baseline automatically.
2. Ask for an existing official profile name, or a new unused profile name and the HTTPS endpoint shown in the Windows DART AI Agent window > Settings > Remote Access. The Windows owner starts DART, selects a Linux-reachable network adapter, enables Remote Access and chooses **Pair a CLI**. No WSL/shared-drive/fixed-port assumption applies.
3. Register only when needed. Give the user a ready-to-run command with the actual absolute installed executable path and shell-appropriate quoting, followed by `connection pair --endpoint HTTPS_URL --profile PROFILE`; have them run it in their interactive terminal and enter the six-digit PIN shown in the Windows app. A noninteractive agent must hand off this step; do not request or record the PIN in chat, command arguments, output or evidence. After pairing, inspect the new profile as below. Default private store is `~/.dart/connections`, or the user's DART_CLI_PROFILE_DIR. Do not edit, replace or copy profile JSON into the skill. If the user explicitly chooses legacy bundle enrollment, use `connection enroll --profile PROFILE --stdin < /private/bundle.json` without printing the bundle.
4. Run `"$DART" app inspect --profile PROFILE` to discover the intended app and record data.appId. Require ok=true, observation.source=connected-main and observation.appId=data.appId. Then run `"$DART" app inspect versioned --profile PROFILE --app APP_ID` with that explicit app ID. Require ok=true, matching appId and connected-main observation, and Main data.version, data.protocolVersion and every data.contract field in the versionedContract independently matching step 1 and the distribution pin. Never replace Main evidence with local identity.
5. Inspect the explicitly selected app using `--app APP_ID` and list its current windows with `"$DART" window list --profile PROFILE --app APP_ID`. A current explicit target takes precedence over a previous binding. Resolve it against the current list; if absent or ambiguous, explain and ask the user, never substitute another window. If there is no current explicit target, prefer a previous selection only when its app and window still match and are available. If that previous target disappeared or the app changed, report it and ask which target preserves the user's intent; do not automatically substitute even a sole remaining window. Only with no previous selection choose the sole window; for zero windows ask the Windows owner to open one, and for multiple candidates present their public IDs/roles and ask. Do not use GUI focus as a selection rule or execute business commands while ambiguous.
6. If a retained session belongs to the selected app and window, inspect it with `"$DART" session inspect --profile PROFILE --app APP_ID --json '{"windowId":"WINDOW_ID","sessionId":"SESSION_ID"}'`. Reuse only if all returned identities match and state=open and windowState=open. A previous session for a different target must never be reused.
7. If the session is missing or invalid, recheck the app and current window list. Preserve the current explicit target or prior user intent. If that exact window is still available and the user requested control, create a new session for it; otherwise ask for clarification rather than silently switching targets. Do not replay any command with an unknown outcome.
8. For a selected window requiring a session, run `"$DART" session create --profile PROFILE --app APP_ID --json '{"windowId":"WINDOW_ID"}'`. Require returned windowId equals the selected ID and state=open. Inspect the resulting session as in step 6, then retain the explicit profile/appId/windowId/sessionId on every subsequent command. GUI focus changes do not change this binding. Reinspect before reuse and stop on errors until the target is revalidated.

On errors, preserve the official code/phase/nextAction in a credential-free report. Connection refused, timeout or unreachable endpoint: Windows owner checks app running, Remote Access, endpoint, firewall/network; Linux checks routing to the issued endpoint. Disabled Remote Access: Windows owner enables it. Expired, cancelled or failed pairing: ask the Windows owner to start a fresh pairing and repeat the interactive step; do not replay unknown outcomes. For explicitly chosen legacy enrollment, request a fresh bundle. Trust/certificate change: verify the intended Windows app with its owner before explicit forget/re-enroll. PROFILE_UNAVAILABLE: Linux verifies profile name/location or registers a new profile by pairing. Version/protocol/contractVersion/fingerprint mismatch or missing versioned identity: install the compatible pinned CLI/app; no business commands. Unknown outcomes require inspection, never blind replay.
