# SQL, analysis and Windows export

Use the revalidated explicit profile/app/window/session and a ready Dataset. Ask for missing analysis intent, source, output format or absolute Windows destination. Do not copy Dataset files to Linux or imply that an export is transferred. Use `command list` and offline `command inspect --json '{"command":"..."}'` only for the relevant commands; validate current inputs with `input inspect`. There is no separate API or transport. Use fresh request IDs for distinct mutations, fresh scoped preconditions, and inspect an unknown outcome before any retry.

## SQL Results

`builder list` identifies available Dataset aliases. Inspect `builder create`, `builder inspect`, `builder edit`, `builder preview`, and `builder save`: create a draft, bind the exact Dataset and alias, edit SQL, preview, wait for the same task and inspect the preview. Save the intended definition when the user's requested result/export requires it; this is a Workspace change. If the user has not authorized the necessary change, explain and ask. Preview is bounded and is not the full published result.

Inspect `results inspect` and `results prepare` (or `results reprepare` for an explicitly intended new generation), use the current scoped proof, wait for the returned task and inspect the exact published `resultId`. A previous successful publication can remain after a failed or cancelled task; do not present it as the new result. Inspect `results metadata`, wait for its task, then read `results page` with its cursor and continuation until the requested evidence is complete. Preserve typed values, limits and truncation; do not infer full results from a preview or a single bounded page.

## Charts, Pivot, Comparison

Inspect the relevant source and exact published generation before creating a captured analysis. For Charts inspect `charts create`/`charts tag-source inspect` and `charts create-from-tag`; for Pivot inspect `pivot results-source inspect`/`pivot source inspect` and the matching create command; for Comparison inspect `comparison sources` and `comparison create`. Read each selected command's schema and eligibility before editing, running or showing. Use current source and draft preconditions and explicit mappings; never silently substitute a later generation. Run and wait on the exact task, then inspect the applied result and read evidence through the appropriate public result command (for example `pivot cells` or `comparison samples`). A successful Main result does not prove renderer adoption or display; use the relevant display wait only when requested. Failure or cancellation may preserve an earlier applied result: identify it and do not call it the new result.

## Task and export status

Acceptance, running, cancel requested, committing, succeeded, failed and cancelled are distinct. `task status` returning `ok:true` means the lookup worked, not that the task succeeded. `task wait` waits for the original task; `WAIT_TIMEOUT` and disconnect do not cancel it. Recheck the same task after timeout or an unknown outcome. A cancellation request is not terminal cancellation; commit may win. Report the terminal state, error and public next action; do not claim success without terminal success and the requested actual result.

For CSV, JSON or Parquet inspect `results file inspect`, `tag file inspect` or `charts file inspect` for the requested source. Supply an explicit format and matching extension, absolute Windows output path and the exact source/result identity. Results require savedViewId/resultId and ordered columns; Tag requires ordered columns and an explicit source range; Charts requires the current resultId/appliedRevision. Inspect each schema for full-export variants. Parquet requires the documented single-Dataset/single-definition lineage; report ineligibility instead of changing format or source silently. JSON contains ordered metadata and text rows, so do not promise the same typing as Parquet.

Keep the same format, source, ordered columns, range, output path and overwrite intent through preflight and export. Respect the command's proof namespace and obtain a fresh scoped proof. Never overwrite without explicit authorization. Wait for the original export task and examine terminal success, path, row count and actual bytes/hash. For a chart image inspect `charts png inspect` and `charts png export` separately. Failure, cancellation, missing result, stale proof, existing destination or inaccessible path must be reported with the public error and corrective action. Never treat a preflight or accepted task as a file.

The export is written on Windows. Verify existence and content from Windows using an authorized Windows-side method when available; compare the actual bytes or content and reported destination. If independent file access is unavailable, report that limit and only the public receipt, not verified content. No Linux file or automatic transfer is implied. Report separately the requested work, changes, task states, actual results, Windows export path and what remains unverified.
