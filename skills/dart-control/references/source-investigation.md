# Dataset source investigation

Use the explicit revalidated profile/app/window/session and the intended Dataset ID. Read `dataset.md` for DM/Tag query procedures. Inspect `dataset inspect` and check readiness and `sourceBinding` for this Dataset; a Windows input or SQLite path is not a Linux source root. Bindings belong to individual Datasets, even when their relative file names match.

If `sourceBinding.state` is unregistered, ask the user for the absolute Linux source root unless already supplied. If a binding exists and the user explicitly requests a different root, confirm the supplied directory and replace the binding using the same procedure; otherwise retain the existing binding. Confirm that it exists and is a directory on this Linux host. Only for initial registration or an explicitly requested replacement, inspect the public `dataset source set` contract, then use the `sourceBinding.precondition` from a fresh `dataset inspect` with the same window, session and Dataset, `environment`, `workspaceRoot` and optional `revisionReference`; use a fresh request ID. Reinspect to verify the stored binding. This stores metadata in the Dataset; it neither probes nor transfers source files. Never replace an existing binding without the user's instruction. If a write outcome is unknown, inspect before another mutation.

Open and query the DM view using the public commands in `dataset.md`. Take the recorded DM `file` and `source_line` from the relevant log row, not the input file provenance or DM `LineNo`/Tag `lineNo`. Log row numbers identify Dataset records; source lines identify lines in a source file. Resolve the recorded relative path under this Dataset's bound Linux root and read the exact file and one-based source line, with enough surrounding context to understand it. Verify the resolved path stays under the root, including after resolving symlinks. Do not search by basename, guess build-directory mappings, or substitute a similarly named file. If the recorded path is absolute, escapes the root, lacks a usable line, or cannot be resolved as recorded, ask the user to clarify the mapping; do not invent one.

Distinguish an unregistered binding, a root that does not exist or is not a directory, a missing exact file, an unreadable file, and a line outside the file. Explain the specific issue and ask for the correct root or path. A stored root is metadata, not proof that it exists on this host. Report the Dataset ID, log row number, recorded path and source line, actual file and quoted line/context, and the resulting inference and limits. Do not infer a numeric mismatch from a rounded DM display string; inspect the corresponding Tag typed cell before comparing such values. A revision reference is descriptive, not proof that the source matches the binary or that a mismatch caused execution. Never claim to have verified source that was not read.
